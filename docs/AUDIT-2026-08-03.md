# Технічний аудит — 03.08.2026

## Виправлено під час аудиту

- Прибрано закомічені Git conflict-маркери у 34 Java-файлах; відновлена версія проходить тести.
- Попередження, мути, бани, історія покарань і антиспам ізольовані ключем `chatId + userId`.
- Налаштування групи реально підключені до welcome/moderation flow у `MickeyHandler`.
- Додано 9 наданих invite-посилань; три нові групи й виправлене посилання «Туризм після 9».
- Додано чотири PNG-звіти: група, активність, баланс/заробіток, глобальна статистика.
- `.env` і `mickey.db` не відстежуються Git; токен у коді не знайдений.
- Права бота й адміністраторів кешуються; scheduler робить примусову перевірку без API-виклику на кожне повідомлення.
- Invite-посилання перенесені в `managed_study_groups`, додано seed, active-статус, `/groupadmin` і web CRUD.
- `/groups` заборонена в приватних повідомленнях, щоб не роздавати закриті інвайти стороннім.
- `ddl-auto=update` замінено на Liquibase + `ddl-auto=validate`; міграція перевірена на порожній і legacy SQLite.
- Розсилки мають атомарний claim, retry/backoff, dead-letter, cancel/retry та відновлення завислих задач.
- Python-діаграми працюють через bounded executor і хвилинний кеш; `/clear` використовує спільний scheduler.
- Додано retention аудит-логів, вимкнено зберігання тексту повідомлень за замовчуванням, індекси й SQLite busy timeout/WAL.
- Додано Spring Security web-панель, health/metrics і online-consistent backup-скрипт.

Старі глобальні рядки варнів/покарань не мігруються до конкретної групи: у них немає `chatId`, тому автоматична прив'язка могла б створити хибні бани.

## Що лишилося після hardening

### Високий пріоритет

1. Для кількох одночасних інстансів перейти з SQLite на PostgreSQL. Поточна SQLite-конфігурація розрахована на один процес.
2. Додати до інвайтів окремі `verificationStatus`, `verifiedAt`, `verifiedBy` і `expiresAt`. Автоматично перевірити приватний invite через Bot API неможливо.
3. Поставити web-панель за HTTPS reverse proxy, додати окремі ролі операторів і журнал адміністративних змін.

### Середній пріоритет

1. Розділити великі legacy-сервіси `AdminCommandService` і `MessageService` на окремі use cases.
2. Завершити міграцію старих boolean-методів команд: `CommandManager` уже використовує `CommandAccess`, але compatibility-методи залишені.
3. Додати ширші Telegram contract-тести максимальних довжин і форматування; Spring/SQLite/security smoke-тести вже є.
4. Оновити Telegram Bots API й прибрати deprecated Gradle/API-виклики перед переходом на Gradle 9.
5. Додати власні Micrometer counters для Telegram/Python/broadcast; зараз доступні Actuator metrics і структуровані логи часу рендеру.
